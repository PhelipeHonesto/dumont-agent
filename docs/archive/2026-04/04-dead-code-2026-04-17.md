### F-04-1 — `_resetDealCounter()` is a no-op kept for tests

**Severity:** MODERATE · **Location:**
`src/orchestrator/deal-context-manager.ts:132-135` · **Effort:** S

```ts
/** No-op — kept for backwards compatibility with tests. ULIDs are globally unique. */
export function _resetDealCounter(): void {
  // ULIDs don't need resetting — they're globally unique by design.
}
```

Called from `beforeEach(() => _resetDealCounter())` in 4 test files:
- `tests/sourcing.test.ts` (4 call sites)
- `tests/composite-updates.test.ts` (6 sites)
- `tests/integration/end-to-end.test.ts`
- `tests/integration/error-paths.test.ts`

**Fix**: delete the function AND the 12 `beforeEach` calls. No behavior
change (it's a no-op); tests stay green. Two-touch search-and-replace.

### F-04-3 — `tripCompleted` legacy field still in use

**Severity:** LOW · **Location:**
`src/schemas/composite-objects.ts:145` + `src/memory/composite-stores.ts:402,465`
· **Effort:** L

```ts
// Legacy (kept for backward compat, mapped from tripOutcome)
tripCompleted: z.boolean().nullable().default(null),
```

The field IS read from and written to the DB via composite-stores. It
shadows `tripOutcome` — same information, different shape. Can't just
delete; would need a migration + ledger backfill to drop the column.

**Recommendation**: keep as-is. Only worth the effort if we're already
migrating the `validation_ledger` table for unrelated reasons.
