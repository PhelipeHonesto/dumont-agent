### F-02-1 — XSS in `/dashboard` via error-tracker reflection

**Severity:** HIGH · **Location:** `src/server/routes/dashboard.ts:189-197`
· **Effort:** S

The `/dashboard` endpoint is no-auth and renders error-tracker records
into innerHTML without escaping:

```js
for (const e of data.errors.slice(0, 10)) {
  html += '<div class="error-row">';
  html += '<span class="time">' + ago(e.timestamp) + '</span> ';
  html += '<span class="route">' + e.method + ' ' + e.route + '</span> ';
  html += '<span class="msg">' + (e.message || '').substring(0, 120) + '</span>';
  html += '</div>';
}
el.innerHTML = html;
```

`e.route` comes from `req.originalUrl || req.url` in
`src/server/middleware/error-tracker.ts:64` — fully attacker-controlled.
`e.method` and `e.message` are likewise reflected from the original
request or thrown Error's message.

**Attack**: anyone can cause a logged error and inject script:
```
curl "https://api.orangesunshineaviation.com/foo%3C/span%3E%3Cscript%3E...%3C/script%3E"
```
Admin opens `/dashboard` → script runs under the api domain with any
cookies present.

**Fix**: escape all error-tracker field values before concatenating.
Minimal change is a helper:
```js
function esc(s) { return String(s ?? '').replace(/[&<>"']/g,
  c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c])); }
// then: esc(e.method), esc(e.route), esc(e.message)
```
Apply to all 7 `innerHTML =` sites in this file for defense-in-depth —
several currently trust server-controlled values but all are rendered
the same way.

### F-02-2 — `/dashboard` is unauthenticated

**Severity:** MODERATE · **Location:** `src/server/routes/dashboard.ts:11`
· **Effort:** S

Per the file header: "GET /dashboard — no auth, read-only status."
Publicly exposes:
- Fleet size (tracked/airborne/idle/ghost counts)
- Data health status per source
- Quality check results
- Last 10 error routes + messages
- Internal service names

By itself this is information disclosure; combined with F-02-1 it becomes
the XSS delivery surface. Error messages can leak stack traces if the
error-tracker ever includes them (currently truncated at 5 lines and
stored as `stack` but not rendered on /dashboard — this is OK).

**Recommendation:** add auth middleware (same pattern as
`/api/chat` / `/chat/completions`) or gate behind a Basic Auth env var.
If it truly must be public, drop the errors panel entirely.

### F-02-5 — No SQL injection

**Severity:** — · **Location:** n/a

Grep for `${...}` inside SQL strings matched 7 sites; every one is
table-name/placeholder generation from code-controlled identifiers, not
user input:

- `src/memory/bulk-upsert.ts:44,58` — `table` + `conflictList` from caller.
- `src/memory/webhook-dedup.ts:47` — `TTL_HOURS` const.
- `src/ingestion/faa-daily-diff.ts:378` — generated `$2, $3, …` placeholder string.
- `src/memory/migrate-data.ts:171,258` — table name from the internal `TABLES` list.
- `src/memory/knowledge-graph.ts:331` — generated placeholder string.

All runtime-variable data uses `$n` parameterized placeholders via `pg`
or bound params via `better-sqlite3`. No dynamic-user-input → SQL paths.

The `sanitize.ts` middleware also blocks SQL meta-patterns
(`DROP|DELETE|UPDATE|INSERT|--|;`) on free-text inputs as defense in depth.
✓

### F-02-8 — `execSync` with interpolated paths (CLI only)

**Severity:** LOW · **Effort:** S per site · 14 sites

All shell-out sites use double-quote template strings around paths:

- `src/ingestion/parquet-ingest.ts:242`, `faa-docindex-ingest.ts:199`,
  `airmen-ingest.ts:258,276,314`, `faa-full-ingest.ts:84`,
  `faa-daily-diff.ts:175,196`, `history-backfill.ts:155,233,244`

A few use the safer `JSON.stringify(path)` quoting:

- `src/ingestion/package-positions.ts:400,407`, `cross-validate.ts:217`

Exposure: these scripts run from the operator shell or the pipeline
orchestrator with code-controlled args. If an attacker could influence
CLI args (e.g. by convincing an operator to paste a malicious `--from`
date), a path with embedded `"` would break out of the quoting. Date
args flow through `new Date(...).toISOString().slice(0,10)` which
neutralizes metadata.

**Recommendation** (defensive hygiene, not an exploitable bug):
replace raw `"${path}"` interpolation with `JSON.stringify(path)`
consistently, or switch to `execFileSync(cmd, [args...])` so the shell
isn't in the loop at all.
